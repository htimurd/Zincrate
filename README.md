# Zincrate — Aero GDPS

Сайт со списком уровней сервера Aero GDPS: рейтинг уровней (название, автор,
сложность, звёзды, картинка, ID, кем проверено), вход через Google, приём
результатов от игроков и админ-панель для управления списком.

Стек: Node.js + Express + EJS + PostgreSQL + Google OAuth (Passport.js).

## Почему данные не пропадут при падении или редеплое

Все данные (уровни, пользователи, заявки, даже сессии входа) хранятся во
**внешней базе PostgreSQL**, а не на диске самого сервиса. Диск Render
пересоздаётся при каждом деплое и перезапуске — а база данных живёт отдельно
и не зависит от того, что происходит с самим веб-сервисом. При старте сервер
сам создаёт нужные таблицы, если их ещё нет (см. `db.js`), так что после
первого запуска ничего вручную настраивать не нужно.

## 1. Локальный запуск (не обязательно, но удобно для проверки)

```bash
npm install
cp .env.example .env
# заполните .env своими значениями (см. ниже)
npm start
```

Сайт откроется на `http://localhost:3000`.

## 2. Настройка входа через Google

1. Зайдите в [Google Cloud Console](https://console.cloud.google.com/).
2. Создайте новый проект (или выберите существующий).
3. Перейдите в **APIs & Services → OAuth consent screen**, выберите тип
   **External**, заполните название приложения (например, «Zincrate»).
4. Перейдите в **APIs & Services → Credentials → Create Credentials →
   OAuth client ID**, тип приложения — **Web application**.
5. В поле **Authorized redirect URIs** добавьте:
   - `http://localhost:3000/auth/google/callback` (для локальной проверки)
   - `https://ВАШ-АДРЕС.onrender.com/auth/google/callback` (после того как
     узнаете финальный адрес сайта на Render)
6. Скопируйте **Client ID** и **Client Secret** — они понадобятся в
   переменных окружения `GOOGLE_CLIENT_ID` и `GOOGLE_CLIENT_SECRET`.

## 3. База данных PostgreSQL

Нужна любая внешняя PostgreSQL-база — подойдёт:

- **Render PostgreSQL** — создаётся прямо в том же аккаунте Render
  (Dashboard → New → PostgreSQL). Проще всего, но на бесплатном тарифе
  Render ограничивает срок жизни базы (обычно 30–90 дней), после чего её
  нужно пересоздавать.
- **Neon.tech** или **Supabase** — у обоих есть постоянный бесплатный тариф
  без ограничения по времени. Рекомендуется, если хотите не пересоздавать
  базу время от времени.

В любом случае вам нужна строка подключения вида:
```
postgresql://user:password@host:5432/dbname
```
Она идёт в переменную `DATABASE_URL`.

## 4. Деплой на Render.com

1. Создайте новый репозиторий на GitHub и загрузите туда все файлы из
   архива (все они лежат одним уровнем — можно просто перетащить их все
   разом в веб-интерфейсе GitHub, «Add file → Upload files»).
2. В Render: **New → Web Service**, подключите репозиторий.
3. Настройки сервиса:
   - **Build Command:** `npm install`
   - **Start Command:** `npm start`
   - **Environment:** Node
4. В разделе **Environment → Environment Variables** добавьте:

   | Ключ | Значение |
   |---|---|
   | `DATABASE_URL` | строка подключения из шага 3 |
   | `SESSION_SECRET` | любая длинная случайная строка |
   | `GOOGLE_CLIENT_ID` | из шага 2 |
   | `GOOGLE_CLIENT_SECRET` | из шага 2 |
   | `GOOGLE_CALLBACK_URL` | `https://ВАШ-АДРЕС.onrender.com/auth/google/callback` |
   | `ADMIN_EMAIL` | `cu16106timur@gmail.com` |

5. Запустите деплой. После первого успешного старта вернитесь в Google Cloud
   Console и убедитесь, что итоговый адрес `onrender.com` добавлен в
   Authorized redirect URIs (шаг 2.5).

## Как работают роли

Никакого отдельного «списка админов» в базе нет — админом считается
единственный пользователь, чей email при входе через Google совпадает со
значением переменной окружения `ADMIN_EMAIL`. Чтобы сменить админа, достаточно
поменять эту переменную в настройках сервиса на Render — код менять не нужно.

Обычные пользователи после входа через Google могут открыть любой уровень и
отправить ссылку на видео своего прохождения — заявка попадает в очередь
`/admin/submissions`, где админ одобряет её (тогда результат появляется в
таблице «Одобренные результаты» и в общем рейтинге игроков) или отклоняет.

## Структура проекта

Все файлы лежат одним уровнем, без подпапок:

```
server.js                    — точка входа, настройка Express и сессий
passport-config.js           — стратегия входа через Google
db.js                        — подключение к Postgres и создание таблиц
auth-middleware.js           — проверка «вошёл в систему» / «это админ»
auth-routes.js               — /auth/google, /auth/google/callback, /auth/logout
levels-routes.js             — страница уровня + добавление/изменение/удаление (админ)
submissions-routes.js        — отправка результата + одобрение/отклонение (админ)
view-*.ejs                   — HTML-шаблоны (view-header/view-footer — общие части,
                                остальные — отдельные страницы)
style.css                    — оформление сайта, отдаётся маршрутом /style.css
```

## Картинки уровней

Поле «картинка» — это просто ссылка (`image_url`), которую вводит админ при
добавлении уровня (например, скриншот, загруженный на Imgur, Discord CDN и
т.п.). Если ссылку не указать, вместо картинки покажется заглушка с первой
буквой названия уровня.
